## Vulnerability disposition

Trivy v0.72.0 initially reported `CVE-2026-56852` in
`golang.org/x/text v0.30.0`. The advisory affects malformed UTF-8 handling in
`norm.Iter`. The official govulncheck v1.6.0 symbol analysis reported zero
reachable vulnerabilities, and binary symbol inspection confirmed that
`norm.Iter` is not linked into the exporter.

The repository therefore publishes one OpenVEX statement with status
`not_affected` and justification `vulnerable_code_not_in_execute_path`, scoped
to the exporter and the exact `x/text v0.30.0` subcomponent. Release CI reruns
govulncheck before applying the VEX. Trivy continues to fail on any other HIGH
or CRITICAL finding; no ignore file, severity downgrade, or database bypass is
used. The v1.0.0 Release workflow passed Trivy for Linux amd64 and arm64.
